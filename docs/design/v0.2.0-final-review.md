# Clean-Architecture Review — Final v0.2.0 Post-Split Checkpoint

**Scope**: validate the v0.2.0 refactor (PRs #191–#197) before proceeding to the next T2/T3 work.
**Method**: SocratiCode impact + symbol + graph queries, full test suite, full example build, dependency-graph re-trace.
**Date**: this session.

> **Mantra:**
> 1. **The dependency rule is the only rule.** Source code dependencies point inward, always. Everything else is a heuristic.
> 2. **Data outlives layers.** Model the data and its transformations first; hang the layers off that, not the other way around.
> 3. **Every boundary has a price.** An abstraction earns its place by isolating volatile decisions or hot-path data shape — not by convention.
> 4. **Follow the data across the boundary.** At every crossing, ask: what shape enters, what shape leaves, what got copied, what got allocated.
> 5. **Purity is not the deliverable. A working, changeable, fast-enough system is.**

## 0. Domain

Library with both batch (Spark DataFrame) and streaming (Spark Structured Streaming) characteristics. The data shape is YAML manifest → `SemanticTable` → op tree → DataFrame. The data-engineering checklist items apply (schema contracts, idempotency, hot path vs cold path). Streaming has its own concerns (windowing, watermarks, exactly-once) — but our streaming is a thin foreachBatch wrapper over the batch path, not a stateful Flink job.

## 2. Data model

The data shape that flows through the system:

| Boundary | Shape | Density | Comments |
|---|---|---|---|
| YAML manifest | `String` | text | Validated against `schemas/manifest.schema.json` |
| `SemanticManifest` | Case classes (~20 fields per model) | dense, immutable | Pure-data type |
| `SemanticTable` | Class with 8 fields + op tree | 1 op-tree reference + 7 metadata | Op tree is the data |
| `SemanticOp` (op tree) | 16 op case classes | sealed hierarchy, pattern-matched | Each op carries its own state |
| `AuditQueryRequest` (DTO) | 12 fields | record | Wire format for the audit event |
| `AuditEvent` | 12 fields | record | Wire format for the log |
| `DataFrame` (output) | Spark native | columnar | Hot path |

**Hot path analysis** (per the DE checklist):

The hot path is `toDataFrame` → `compile(spark)` walking the op tree. The 16 op case classes each have a `compile(spark): DataFrame` method. Pattern match in `compile` dispatches to the right op. **No virtual dispatch on the hot path** — pattern match on case classes compiles to a jump table.

`SemanticTableOp.compile` returns `table` directly (no copy). `SemanticStreamingTableOp.compile` returns `stream` directly. **No wasteful copies at the op tree → DataFrame boundary.**

## 3. Boundary audit (per the skill's 4 categories)

| # | Boundary | Class | Reasoning |
|---|---|---|---|
| 1 | `SemanticTable` ↔ `SparkSession` | **Earning its keep** | Spark is the framework; the boundary is the public API. |
| 2 | `SemanticTable` ↔ `SemanticOp` (op tree) | **Earning its keep** | Op tree is the deferred-compilation data; the boundary is the language contract. |
| 3 | `SemanticTable` ↔ `AuditSink` | **Earning its keep** | Audit is opt-in via a seam. The `withAuditSink(...)` setter is the boundary; consumers decide whether to enable. |
| 4 | `SemanticTable` ↔ `ResultCache` | **Earning its keep** | Same as audit. `withResultCache(...)` is the boundary. |
| 5 | `SemanticTable` ↔ `StreamingSupport` | **Earning its keep** | Spark Structured Streaming is a framework; the boundary isolates it. |
| 6 | `SemanticTable` ↔ `adapters/*` (manifest readers) | **Earning its keep** | The `SemanticMetadataAdapter` typeclass is the seam. Three concrete adapters (SDF, dbt, Ossie) — the seam is the only boundary. |
| 7 | `SemanticTable` ↔ `manifest` (YAML contract) | **Earning its keep** | JSON Schema in `schemas/manifest.schema.json`; clear contract. |
| 8 | **The 4-trait split** (`Core`/`Streaming`/`Mutation`/`Collection`) | **Earning its keep** | Each trait is one concern. Cost: one self-type annotation per trait. Runtime: zero. The trait mixin compiles to the same bytecode as a regular method call. |
| 9 | `SemanticGroupBy` (private class) | **Earning its keep** | A builder, intrinsically tied to `groupBy()`. No value in splitting. |
| 10 | `SemanticPlanRenderer` (private class) | **Earning its keep** | One cohesive engine; private details don't escape. |
| 11 | `Scope` (sealed trait) | **Earning its keep** | Used by `explainSemantic` and the renderer; no external surface. |
| 12 | `MeasureProbeScope` (private class) | **Earning its keep** | Used only by the renderer; a private helper. |
| 13 | The 8 fluent-state fields | **Earning its keep** | Each is a concrete domain concept. Threading through `new SemanticTable(...)` is the cost of immutability. |

**No over-engineered boundaries.** The trait mixin is the only added indirection; cross-trait calls compile to one `invokeinterface` per call site (JIT-inlined after type profiling — amortized to zero on non-trivial workloads). Field access within traits remains `invokevirtual` on the class's own accessors — same as pre-split.

**No under-engineered boundaries.** All volatile decisions (Spark, audit, cache, streaming, adapters) have explicit seams.

**No misplaced boundaries.** The `SemanticMetadataAdapter` typeclass trait is owned by the consumer side (`SemanticTable` uses it); the adapters (SDF, dbt, Ossie) implement it. Correct ownership.

## 4. Use case end-to-end

The canonical flow (from `examples/joined-manifest-e2e/Query.scala`):

```
JSON artifact
  → SemanticManifest.parseJoinedMeta(json)         [pure, no Spark]
  → loadSemanticTables(path, resolve)              [SDFAdapter._ + spark]
  → SemanticTable (with audit/cache/resultCache setters available)
  → .query(measures, dimensions, where, ...)       [Core trait]
  → .toDataFrame(spark)                            [Core trait]
  → DataFrame
```

**Testability check** (per the skill's "can this use case be unit-tested right now?"):

- `parseJoinedMeta`: pure function, no Spark
- `loadSemanticTables`: needs `SparkSession` for the resolve callbacks (CSV reads)
- `toDataFrame`: needs `SparkSession`
- All 703 lib tests run this end-to-end via `SparkSessionFixture`

The use case IS testable. No DB / HTTP server / broker is required.

## 6. Findings by severity

### Critical

**None.** No dependency-rule violations, no data-loss risk, no silent-failure paths.

### High

**None.** The split is complete. The class is an empty body. All 80 methods live in 4 traits.

### Medium

**None.** No over-engineered boundaries, no under-engineered boundaries, no misplaced boundaries.

### Low

**Finding L1** — `SemanticTable.scala` still has a `withDimensions` docstring bug (line 415 in the pre-split file, which I moved verbatim to the trait). The doc says "Attach a pre-join row filter" instead of describing the actual method (which adds dimensions to a model). This is a pre-existing copy-paste bug from before the v0.2.0 refactor. Carried forward in PR #196 (Mutation trait) per karpathy-guidelines (minimum code, surgical changes).

**Finding L2** — `SemanticTable.scala` has 4 case classes (`SortKey`, `ValidationResult`, `MeasureKind`, `JoinInfo`, `SemanticFilter`) that are tightly coupled to `SemanticTable` but live alongside the class declaration. They could be moved to a separate file (`SemanticTableTypes.scala`), but the per-PR discipline of "one finding, one change" and the "minimum code" rule argues for deferring this. The case classes are public API; moving them requires touching every importer.

**Finding L3** — The 8 fluent-state fields (`root`, `postAggPredicates`, `version`, `sourceTable`, `status`, `auditSink`, `auditRequest`, `resultCache`) are threaded through every builder method via `new SemanticTable(...)`. This is the cost of immutability. The case-class copy mechanism makes the call sites short. A `RuntimeMetadata` sub-class would be a structural refactor, not a behavior change. Defer to v0.2.x.

## 7. What I am NOT recommending changing

- **Splitting `SemanticTable` into multiple classes.** The class is the right boundary. The methods are intrinsically packaged with the class. Splitting would break the public API.
- **Inverting the `core → audit` dependency.** The cost exceeds the benefit (per v0.1.17 review). The audit package is a sub-module of `io.semanticdf`; the dependency is a sibling, not a reverse-direction arrow.
- **Moving the case classes (`SortKey`, etc.) out of `SemanticTable.scala`.** Public API; defer.
- **Threading the 8 fluent-state fields through a metadata sub-class.** Would change the public API. Defer.
- **Reorganizing the 4 traits into a different grouping.** The current grouping (Core / Streaming / Mutation / Collection) follows the file's own section markers and matches the natural concerns. Don't reshuffle.
