## Pending

### PR 2: Scope cleanup (auto-safe, internal refactor)

**Fix 6** — `src/main/scala/io/semanticdf/Scope.scala`

Currently has 3 implementations (BaseScope, JoinScope, StreamingScope) with identical `apply(name): Column` signatures. The clean-architecture review flagged this as "misplaced-ish" — they could be one parameterized class.

**Plan**: Make `Scope` a sealed trait with `private[semanticdf] case class BaseScope(df)`, `case class JoinScope(left, right, alias)`, etc. Keep the public `SemanticScope` trait the same; only the concrete implementations change.

**Verify**: All tests that resolve a scope (every `withDimensions`/`withMeasures` test) pass.

**Blast radius**: Internal — Scope is used by Dimension/Measure lambdas; users don't reference it directly. ~10 callers in the codebase.

**Risk**: LOW (auto-safe, behavior-preserving).

### PR 3: CacheKey encoding extraction (auto-safe, internal refactor)

**Fix 7** — `src/main/scala/io/semanticdf/cache/CacheKey.scala`

The 4 `encode*` helpers + `prefixSize` are private to `CacheKey`. As cache usage grows, this encoding may be reused for other hash-keyed storage. Move to a new `src/main/scala/io/semanticdf/cache/LengthPrefixed.scala` and have `CacheKey` delegate.

**Plan**: Create `LengthPrefixed` object with `encodeString`, `encodeOptString`, `encodeMap`, `encodeOptPair`, `encodeList`, `encodePairList`, `prefixSize`. `CacheKey` calls these.

**Verify**: All 36 cache tests pass.

**Blast radius**: Internal — only `CacheKey` uses these.

**Risk**: LOW (auto-safe, behavior-preserving).

### PR 4: SemanticTable split (the v0.2.0 headliner)

**Fix 5** — `src/main/scala/io/semanticdf/SemanticTable.scala`

80 methods, ~3000 lines. Mixes data loading, query construction, audit emit, cache management, streaming terminal, op tree mutation.

**Plan**: Split into 4 files:
- `SemanticTable.scala` (core class — construction, op tree access, ~30 methods)
- `SemanticTableQuerying.scala` (query builder, toDataFrame, audit, cache — ~20 methods as implicit class or trait)
- `SemanticTableStreaming.scala` (toStreamingQuery, StreamingValidator delegation — ~15 methods)
- `SemanticTableMutation.scala` (withDimensions, withMeasures, withRowFilter, groupBy, aggregate, etc. — ~15 methods)

**Verify**: All 703 lib tests + 130 MCP tests pass.

**Blast radius**: MASSIVE — every example, every test, the MCP server all call `SemanticTable` methods. This is the "v0.2.0 era" change. Must be done as a single coordinated commit with the test suite green.

**Risk**: HIGH in code terms (large rename across the codebase), but LOW in behavior terms (no logic change). The compiler will catch every error.

## What I'm NOT recommending

- **Inverting the `core → audit` dependency** — the cost exceeds the benefit (per clean-architecture review).
- **Removing `private[audit]` from `InMemoryAuditSink`** — deliberately scoped; widening is a v0.3+ decision.
- **Building a `backfill` vs `scheduled` split** — the library has no such divergence.
